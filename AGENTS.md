# AGENTS.md

Foundry VTT **module** (`knight-damage`) that adds damage-apply tooling on top of the French _Knight_ TTRPG system (`relationships.systems: knight`, Foundry V14 min/verified). Built from the League FoundryVTT Module Template (gulp + rollup). Vitest unit suite in `tests/unit/`; no TypeScript.

## Commands

- `npm run build` — clean + rollup bundle + styles + static copy into `dist/`. `npm run build:watch` for watch mode.
- `npm run lint` (eslint flat config) and `npm run format` (prettier). **Staged files are linted/formatted on pre-commit via husky + lint-staged, and the unit suite runs in the hook too** (0.3s); full lint+test run in CI. Unit tests: `npm test` (vitest, ~0.3s, in CI after lint); e2e (foundryvtt-test-framework) is local-only, NEVER in CI — scaffold + smoke + fixture recording/replay + the Phase-3 damage pipeline (`tests/e2e/damage-knight.test.mjs`, 10 cases / 36 assertions) + the Phase-4 vehicule/mecha suite (`tests/e2e/damage-vehicule-mecha.test.mjs`, 7 cases / 22 assertions, run via `npm run test:e2e:vehicule-mecha` — same snapshot/restore + chat-sink discipline, and its no-leak self-check also DETECTS the FLAGLESS passenger/pilote side cards those recaps create, which the case code then sinks) + the Phase-5 espoir/energie reminders suite (`tests/e2e/damage-reminders.test.mjs`, 6 cases / 23 assertions, run via `npm run test:e2e:reminders` — pins the actor-flag reminder maps on the SPEAKER token's actor with the `.`→`_` uuid key byte-pinned (including PRE-CAP targets so the CdF/penetrant subtraction is observed unsaturated), the FLAGLESS `Dead`-effect death cards by message-id diff, and the flag-namespace baselines of all four actors; the death-card format is unit-pinned in CI too) are green; see `docs/testing-plan.md`. Order: `lint -> test -> build`.
- Unit tests live in `tests/unit/**/*.test.mjs`; Foundry globals are stubbed in `tests/unit/support/foundry-globals.mjs` (setupFiles), doubles in `doubles.mjs`. The knight-damage classes are the test subjects — source is the oracle; author-confirmed intentional oddities are labeled `INTENDED (author)`, unconfirmed oddities stay `CHARACTERIZATION:` pins (see the list in Architecture below for which is which).
- `npm run link-project` — symlinks `dist/` into Foundry User Data. `foundryconfig.json` is gitignored and per-machine: the local one points at the portable v14 install (`Desktop\Foundry v14`); recreate it in fresh worktrees. Linking needs **admin privileges on Windows** (or Developer Mode). `npm run clean:link` removes the link.
- E2E (local-only, NEVER in CI): `npm run prepare:e2e` (build + copy `dist/` into the Foundry data dir as a real file copy) → `npm run setup:e2e` (copies license/systems/modules/world into gitignored `test-data/`) → `npm run test:e2e` (boots a real Foundry + browser via `foundryvtt-test-framework`). Requires a licensed Foundry v14 + the sibling clone `../foundryvtt-test-framework` with its `FoundryVTT-Node/` (a copy of the portable install's `App/resources/app` works — see `docs/testing-plan.md` Phase 0) and `tests/e2e/config.mjs` (gitignored; template `config.example.mjs`). `test-data/` contains a license copy — never commit. Gotchas (junction install needing `--preserve-symlinks`, v14 login-form selector, `--noipdiscovery`, Foundry data-dir lock racing back-to-back runs + the repo-root `.e2e-spawn.lock` ownership mutex that serializes e2e scripts) are in the plan's Phase 1/2 status blocks and `tests/e2e/support/{framework,spawn-lock}.mjs`. Fixture recording: `npm run record:e2e` (real scripted knight attack via `RollKnight` + dice override, dumps `tests/e2e/fixtures/*.json` pinned to the knight system version — ALWAYS as `setup:e2e && record:e2e` one chain: the recorder hard-fails on an unpinned weapon `_id` because test-data is not wiped between records) and `npm run test:e2e:fixtures` (live replay validation) and `npm run test:e2e:damage` (Phase-3 damage pipeline over the fixtures: every case restores the victim `system.*` and deletes its own chat messages — via v14's `ChatMessage.deleteDocuments`, the static `delete` was REMOVED in v14 with no alias, and the suite-end self-check fails loudly if any recap message leaked — so back-to-back runs WITHOUT setup are valid; the recorder also sweeps its pinned weapons from the attacker in a `finally` block (every exit path, including hard-fails), so `record:e2e -> test:e2e:damage` without a re-setup works — but `setup:e2e` before `record:e2e` stays mandatory). The **test world seed is committed** under `tests/e2e/world-seed/` and `setup:e2e` overlays it onto `test-data/` — treat the world copy in the live Foundry Data dir as disposable/re-seedable, never as the source of truth. Seed gotchas: the victim actor row must NOT store `system.aspects` (message `targets[].aspects` is the STORED source; baked runtime values drift the fixture gate); embedded `items[]` in the NEDB actor row survive v14's one-time NEDB->LevelDB migration with pinned `_id`s (never add a top-level `items.db` — it double-creates); `setup:e2e` never copies a SEEDED world from sourceDataPath (EBUSY when the live Foundry desktop app holds its LevelDB files -> half-copied world). Phase 5 (`npm run test:e2e:reminders`, espoir/energie reminders over the same fixtures) additionally pins the actor-level `knight-damage` reminder FLAGS: the flag key (`Actor_<id>` with `.`→`_`, byte-pinned) lives on the ATTACK MESSAGE'S SPEAKER token's actor — victim-speaker replays self-flag, the recorded null speaker drops only the reminder — the `Dead`-ActiveEffect death cards are FLAGLESS (found by message-id diff; the leak scan covers their headers), and the knight system's `_cleanActor` janitor auto-deletes status-LESS effects (regardless of their changes — key-bearing or empty both qualify — as long as all flags are statuscounter-flavored) right after `preCreateActiveEffect` fires, so the `Dead` trigger effect is transient live while the card still emits.
- Node: `lts/*` per `.nvmrc`; CI uses Node 20.

## Build layout (non-obvious)

- Rollup input is `src/module/knight-damage.js`; output is `dist/module/knight-damage.js`. `src/module.json` `esmodules` must keep matching this path.
- Only `src/styles/knight-damage.css` is copied (filename must equal the package id); static copies are limited to `assets, fonts, lang, packs, templates, module.json` (see `staticFiles` in `gulpfile.mjs`) — anything else in `src/` is silently not built.
- In `src/module.json`, the `version`/`url`/`manifest`/`download` fields are literal `"This is auto replaced"` placeholders substituted by `.github/workflows/release.yml` on GitHub release publish. Don't hand-edit them; releases are cut by publishing a tagged GitHub release.

## Architecture

- Entrypoint `src/module/knight-damage.js` wires everything through Foundry `Hooks` (`init` registers status effects and `CONFIG.queries['knight-damage.addReminder']`; `renderChatMessageHTML` injects the damage buttons). The `preUpdateChatMessage` antianatheme injection was an e2e-discovered v14 bug (it read `data.flags.knight.actor.statuses`, a runtime-only derived Set never present in the serialized knight actor snapshot, so the listener threw swallowed `TypeError`s); it is FIXED — statuses are read from the snapshot's serialized `effects[].statuses`, unit-pinned in `tests/unit/entrypoint-dispatch.test.mjs`; the live in-world status e2e case is Phase 3.
- Damage handling is class-per-actor-type: `DamageBase` subclasses (`DamageKnight`, `DamageVehicule`, `DamageMecha`) dispatched by `createDamageObject()` keyed on actor type (`knight`, `vehicule`, `mechaarmure`). `damageBande.js`, `damageCreature.js`, `damageNpc.js`, `damageBaseNpc.js` exist but are **commented out of dispatch and dead code** — don't assume they're live.
- Damage classes read data out of _knight_ system chat messages: `message.flags.knight.*` **and regexes over French HTML fragments** (`Dégâts</div>`, `Débordement</div>`, `<span class="label">…`). Changing knight system chat output breaks these silently.
- All persistent data lives under `knight-damage` document flags (actor, module). Actor UUIDs are stored in flags with `.` replaced by `_` (`generateReminderData` / `generateReminderMessage` rely on this round-trip).
- Debug logging: use `log()` from `src/module/helpers.js`, gated by a `devMode` constant at the top of that file — plain `console.log` is not filtered.
- UI/domain strings are French; commit messages are written in French.
- Behaviors that **look like bugs but are intended** (confirmed by the author) — never "fix" them, unit tests pin them: (1) items like _Cuir du taureau_ / _Instinct du loup_ are active when `system.active.base` is **falsy** (unlike _Rire du corbeau_, which is a plain truthy check); (2) when knight armor is bypassed (`isArmorIgnored()`), damage beyond sante is silently dropped; (3) vehicule/mecha passenger-pilote recap messages carry no `knight-damage` flags — passenger damage is applied and reverted **manually**; (4) `cohesion` repartition intentionally writes `system.sante.value` in `apply()`; (5) colosse `/10` is default-on unless `resilience.value === 0` or `antivehicule` (absent resilience counts as on, incl. mecha); (6) `apply()` always issues two `actor.update()` calls (energie in the second). Fixed genuine oversights: Débordement/Oriflamme fallback now `Math.ceil`s the multiplier like the targets path; a dead `effectiveStats[stat] -= 0` line was removed from `calculateDamageStat`; both dialog callbacks (`askModifier`, `askDamageEnergie`) treat non-finite `valueAsNumber` (empty input, `+Infinity`) as 0 instead of poisoning damage with `NaN`/`Infinity`; and the trait parsers are null-safe — `getTraitValue` on a raw entry without a number **or a negative one (clamped to 0 so a negative `penetrant` can never inflate CdF)**, `extractTraitValue` with a missing label span or bare `+`, and the Débordement numeric fragment (whose regex now also accepts CRLF content) all yield 0/parse instead of `NaN` poisoning or a constructor `TypeError`. A final sweep also made **uuid-resolution failures inert**: the `antianatheme` status fallback skips an unresolvable attacker actor, `calculateEnergie` and the espoir reminder drop only the `addReminder` query (stats stay applied) when the origin or the active GM is null, and the revert-damage click exits early if the token was deleted.

## Conventions

- Prettier: single quotes, semicolons, trailing commas, print width 120. ESLint extends `@typhonjs-fvtt/eslint-config-foundry.js/0.8.0`; Foundry globals (`Hooks`, `game`, `canvas`, `foundry`, …) come from that config — browser-only symbols used in `src/` need `/*global …*/` comments; node globals only allowed in root `*.mjs`/`*.cjs` files.
- To check real Foundry core behaviour/signatures instead of guessing, use the `foundry-vtt-source-access` skill (core source is available locally on this machine).
